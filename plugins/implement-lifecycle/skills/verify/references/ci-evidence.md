# CI evidence for the authoritative suite

Read this before recording `suite-source: ci` in place of executing the authoritative command or plan.

A target-repository required-CI run replaces execution only when every condition holds; a failing, other-SHA, other-repository, or unconfirmable run is not evidence, so execute instead. Parse the repository and run id from the run URL and fetch one attempt with `gh run view -R <owner>/<repo> <run-id> --attempt <n> --json headSha,conclusion,jobs,url`. Require: the repository is the target repository; `headSha` equals `verification-head`; that attempt's `conclusion` is `success`; and in every job or matrix leg with a step running a plan command, each established command maps, in order, to a step whose conclusion is `success`, never `skipped`. Reject the run if a plan step is conditional or `continue-on-error` in the workflow definition the run executed (for `pull_request` runs, the merge ref; the file at the head SHA is supplementary only). Wait for an in-progress run at most the suite's own typical runtime, and never more than 30 minutes, then execute. Record `suite-source: ci`, `suite-ci-run: <run-url>`, `suite-ci-attempt: <n>` (an integer ≥ 1; a CI record without one is rejected), `suite-executions: 0`, `suite-exit-status: 0`, and one `pass`/`0` result per command whose evidence entry names its job and step and holds that step's complete log from the same attempt (`gh run view <run-id> --attempt <n> --log`, or `--job <job-id> --log`). Never use a run for any other SHA.
